# substrate 0.2.0: another machine

2026-10-22. Baseline: 0.1.0 (`af6f27e`, untagged; everything before this
release). Range: `af6f27e..` this release's merge on `main`.

## What it is

Each machine's substrate is now reachable from the other machines it trusts,
live. Its registry, its process control and its events go over one
persistent, authenticated, encrypted connection per caller. Each machine
keeps its own segment: nothing here is shared memory across a wire. What is
added is an adapter in front of each machine's segment.

```sh
sub-net keygen                                  # once per machine
sub-net trust pc pc.pub --at 10.0.0.2:7341      # each machine it talks to
sub-net serve --bind 10.0.0.1:7341              # on the private link's address
sub-net ps pc ; sub-net run pc --name w -- ./w ; sub-net stop pc w
sub-net events pc                               # pushed, one JSON object a line
sub-net listen warp -- ./cell-runner            # a named channel here
sub-net connect pc warp                         # the one on pc
```

## Added

- **`sub_net_transport`**, the seam in `substrate.h`: a transport is a struct
  of pointers that carries whole frames between two authenticated machines.
  The protocol above it is one JSON object a frame.
- **`sub-net`** (`bin/net`, `net.c`): `keygen`, `trust`, `peers`, `serve`,
  `ps`, `run`, `stop`, `enable`, `disable`, `events`, `listen`, `connect`,
  `selftest`, `--version`.
- **The transport `Noise_IK_25519_ChaChaPoly_SHA256` over TCP**, with mutual
  authentication by per-machine X25519 keys, a separate key per direction,
  and forward secrecy.
- **`sub net …`** and **`sub keygen`**, which run the `sub-net` beside `sub`;
  `sub --version`.
- **`test-net.sh`**, run by `test.sh`: two substrates on one Mac joined over
  127.0.0.1 with throwaway key pairs (32 checks).
- **`SUB_RELEASE`** in `substrate.h`: the release number, kept apart from the
  format number `SUB_VERSION`, which is still 8.

## Security

- **The cipher suite is implemented in this repo, in `net.c`.** There is no
  libsodium, no OpenSSL and no third-party code, in keeping with the rest of
  substrate. Every primitive is tested against its published vectors by
  `sub-net selftest`, which the suite runs:
  SHA-256 (FIPS 180-2: `abc`, the two-block message); HMAC-SHA-256 (RFC 4231
  case 2); ChaCha20 (RFC 8439 §2.3.2); Poly1305 (RFC 8439 §2.5.2);
  ChaCha20-Poly1305 (RFC 8439 §2.8.2, ciphertext and tag); X25519 (RFC 7748
  §5.2, and §6.1 both public keys and both sides of the shared secret). Two
  more are properties: a flipped bit in a sealed frame is refused, and a
  low-order public key is refused.
- **The listener is refused anything but a loopback or private address**:
  127/8, 10/8, 172.16/12, 192.168/16, 100.64/10, 169.254/16, `::1`,
  `fc00::/7`, `fe80::/10`. `0.0.0.0`, `::` and every public address are
  refused at `serve`.
- A caller whose key is not on the trust list is refused after the first
  handshake message. A server that cannot prove the key trusted under its
  name is refused by the caller.
- Keys live in the net folder (`$SUB_NET_DIR`, else
  `~/Library/Application Support/substrate/net` on macOS and
  `~/.config/substrate/net` elsewhere), never in the repo. The secret half has
  mode 0600 and is never printed or logged. The suite checks both.

## Changed

- The README's *Another machine* section used to say the network was a
  boundary nothing crosses. It now describes the adapter.
- `make install` / `uninstall` install and remove `sub-net`.

## Known limits

- `sub-net serve` authenticates callers one at a time, with a 5-second limit
  on each, so a caller that stalls mid-handshake delays the next one.
- Each machine still has its own segment: a count or a blob on one machine
  is not on the other.
- A channel has one listener per machine, and every connector to it receives
  everything that listener writes.

## Tests

The full suite on macOS (`test.sh`, under `desk-heavy nice -n 10`, at a load
average of about 60): 256 pass, 3 skip (swiftc twice, docker), 2 fail. Both
failures are the contention storm's load-bound "timeouts stay under 1%" check
at 64 and 128 clients. Its correctness checks pass (no duplicate ids, every
gap an admitted timeout), and this release does not change the ring.
`test-net.sh`: 33/33. `sub-net selftest`: 14/14. The Linux build
was not run on this Mac (Docker's daemon is not running here). It runs in CI
on the push to `main`.
