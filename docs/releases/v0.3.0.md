# substrate 0.3.0: a worker node

2026-10-22. Baseline: 0.2.0 (`afa45a7`). Range: `afa45a7..` this release's
merge on `main`.

## What it is

A Linux machine joined to the Mac as a Substrate worker with one command,
made for the 8-core worker VM. It gets its own registry and its own `sub-net
serve` on the private link, both of which come back after the nightly
shutdown, its own GitHub key for the private repos it reads, and trust both
ways with the Mac.

```sh
scripts/worker-node/join.sh aspen-worker-1 10.20.0.4 ~/.ssh/aspen-worker-1_ed25519 \
    --user azureuser --deploy-repo JoshuaRamirez/Desk-Workers
```

The steps: `install.sh` (tools, build, `~/.local/bin`, the GitHub key),
`identity.sh` (`sub-net keygen`, trust of the Mac) and `serve.sh` (systemd
user units with linger). Each runs on the worker over SSH, and each is
idempotent. The join then trusts the worker on the Mac, registers the deploy
keys read-only, and proves itself with `sub-net ps NAME`. The full account is
in [docs/worker-node.md](../worker-node.md).

## Added

- `scripts/worker-node/install.sh`, `identity.sh`, `serve.sh`, `join.sh`,
  with `--undo` for both ends.
- `sub-net untrust NAME` and `sub-net dir`.
- `test-worker.sh`, run by `test.sh`.
- `docs/worker-node.md`.

## Changed

- `sub-net trust` leaves an entry that is already trusted the same way
  untouched.

## Security

- Key paths only: no script, log or report prints a key value, and the test
  checks what the join printed against every secret key it made.
- Only public halves cross the link: the two `sub-net` key.pubs and the
  GitHub key's `.pub`.
- The worker's GitHub key is a deploy key, read-only (`--allow-write=false`),
  one per named repo.
- The worker serves only on the address it is given, and `sub-net serve`
  still refuses any address that is not loopback or private.
- Nothing is installed or started on the Mac: it is an SSH client and this
  repo's own `bin/net`.
